## ① 기획서

### 1. 문제

HTML을 직접 손으로 작성하는 과정에서, 태그 이름이나 속성을 다 외우지 못해 검색하거나 문서를 뒤적이는 데 시간을 많이 쓰게 된다. 특히 이제 막 HTML을 배우기 시작한 초보자에게는 이 "검색하러 갔다 오는" 과정이 학습 흐름을 자꾸 끊어버리는 문제가 있다.

블록코딩 도구처럼 태그를 화면에서 직접 조립해서, 코드로 렌더링만 되는 게 아니라 실제 요소로 화면에 바로 붙여 넣을 수 있다면, 코드를 손으로 치는 것보다 더 빠르고 직관적으로 HTML을 다룰 수 있을 것이라는 아이디어에서 출발했다.

### 2. 사용자

**주 페르소나**: 이제 막 HTML을 배우기 시작해서, 새로운 태그가 나올 때마다 MDN이나 블로그를 검색해가며 하나씩 따라 치는 학생. 태그 이름과 속성을 아직 다 외우지 못한 상태라, 코드를 치다가도 자꾸 검색창으로 넘어가느라 학습 흐름이 끊기는 상황을 자주 겪는다.

**보조 사용자**: 이미 HTML을 다룰 줄 알지만, 반복적으로 태그를 손으로 타이핑하는 과정 자체가 번거롭다고 느끼는 개발자. 이쪽은 "학습"보다 "속도"가 핵심 니즈.

### 3. 해결 아이디어 (가치가설)

> **HTML 태그와 속성을 검색해가며 손으로 코드를 짜는 게 번거로운 개발자**에게, **태그를 조립해서 화면에 바로 끼워 넣는 기능**을 제공하면, **코딩 속도가 빨라지고 학습에도 도움이 되며 코딩이 더 직관적으로 느껴지는** 문제가 해결된다.

### 4. 핵심 기능 3가지

| 번호 | 기능 | 동작 |
|---|---|---|
| 1 | 태그 선택 & 속성 편집 | 사용자가 태그 종류를 클릭하면, 그 태그에 맞는 속성 입력 폼이 자동으로 나타난다 |
| 2 | 제작 및 배치 | 속성을 채운 뒤 "제작" 버튼을 누르고 원하는 위치를 클릭하면, 구성한 태그가 실제 요소로 화면에 삽입된다 |
| 3 | 실시간 코드 확인 | 태그가 삽입될 때마다 코드부에 들여쓰기와 문법 강조가 적용된 완성 코드가 즉시 반영된다 |

### 5. 시장조사

> **[※ 본인이 직접 조사 후 작성]**
> - 유사·경쟁 서비스 2개: 화면 캡처 + 좋은 점 1줄 / 아쉬운 점 1줄
> - 잠재 사용자 3명에게 짧은 질문 (같은 반 친구 가능): "HTML 짤 때 태그·속성 검색 때문에 흐름 끊긴 적 있어?", "그때 어떻게 해결했어?", "이런 도구 있으면 쓸 것 같아? 왜?"

### 6. 추후 확장 아이디어 (v2 이후)

이번 MVP는 HTML 조립 기능까지만 다루고, 아래 아이디어들은 다음 단계에서 확장할 계획이다.

| 단계 | 아이디어 | 내용 |
|---|---|---|
| v2 | 태그 설명 툴팁 | 태그별 데이터(JSON)에 설명 필드를 포함시켜두고, 태그에 마우스를 오래 올려두면 해당 설명이 렌더링되도록 함 — 구글 검색 같은 별도 행동 없이 페이지 안에서 바로 학습 가능 |
| v2 | CSS 스타일링 | 배경색·글자색·여백(padding/margin)·글자 크기 등 기본적인 스타일 속성을 붙일 수 있는 기능 추가 |
| v2 | JS 인터랙션 | 클릭 같은 이벤트에 미리 정의된 동작(텍스트 바꾸기, 클래스 토글, alert 등)을 연결하는 기능 추가 |
| v2 | 다크/라이트 테마 전환 | 사용자가 에디터 자체의 테마를 다크/라이트로 전환할 수 있는 기능 |
| v2 | 대시보드(마이페이지) 기능 | 사용자 정보(가입 후 지난 날, 만든 프로젝트 수 등) 표시, 저장된 프로젝트를 미리보기 카드로 보여주고 클릭하면 작업 화면에서 이어서 작업할 수 있도록 함 |
| v2.5 | 레이아웃 구성 배치 커스터마이징 | 렌더링부·코드부·태그 편집부 등 화면 영역의 배치를 사용자가 원하는 대로 재구성할 수 있는 기능 |

## ② 사이트맵

### 페이지 구조

처음에는 작업 화면 하나로만 이루어진 단일 화면 도구로 기획했다. 하지만 제출 하루 전, 사용자가 처음 사이트에 들어왔을 때 무엇을 하는 도구인지 알 수 있는 곳과, 자신이 만든 프로젝트를 다시 찾아 이어서 작업할 수 있는 곳이 필요하다고 판단해 **소개 페이지**와 **대시보드(마이페이지)** 두 페이지를 직접 구상해 추가했다.

```
[소개 페이지] index.html
   ├──(대시보드 클릭)──▶ [대시보드] dashboard.html
   │                         └──(새 프로젝트 / 프로젝트 카드 클릭)──▶ [작업 화면] workspace.html
   └──(새 프로젝트 클릭)─────────────────────────────────────────────▶ [작업 화면] workspace.html

(모든 페이지) 로고 클릭 ──▶ [소개 페이지]
```

- **소개 페이지 (index.html)**: 딸깍이 어떤 도구인지 소개하는 첫 화면. 상단에 [대시보드], [새 프로젝트] 버튼. 소개 내용의 자세한 구성은 아직 미정
- **대시보드 (dashboard.html)**: 사용자 간략 정보 + 기존 프로젝트를 갤러리 형식 미리보기로 보여주고, 클릭하면 작업 화면에서 이어서 작업. 대부분의 기능은 v2에서 구현 예정
- **작업 화면 (workspace.html)**: 태그 조립이 실제로 이루어지는 핵심 화면 (아래 컴포넌트 이동 구조 참고)

### 작업 화면 컴포넌트 이동 구조

작업 화면 안에서는 페이지 이동이 없으므로, **한 화면 안에서 컴포넌트가 어떻게 연결되고 사용자의 조작이 어떤 순서로 이동하는지**를 정보 구조로 표현한다.

```
[상단 바: 프로젝트 이름 + 새 탭 / 내보내기 / 저장 / 불러오기 / 초기화]
        │
        ▼
[html 태그 종류] ──(카테고리 선택)──▶ [html 태그 선택 부]
                                            │ (태그 클릭)
                                            ▼
                                   [태그 속성 편집 부]
                                            │ (제작 클릭 → 커서에 붙음)
                                            ▼
                                (렌더링부/코드부 위 클릭 → 배치 확정)
                                            │
                    ┌───────────────────────┼───────────────────────┐
                    ▼                                               ▼
              [렌더링부]  ◀───────── 실시간 동기화 ─────────▶   [코드부]
                                                                     │
                                                              (복사 버튼)
                                                                     ▼
                                                               클립보드로 복사
```

- 정보 구조상 상하 관계: 상단 바(프로젝트 단위 액션) → 태그 구성 영역(카테고리→태그→속성) → 결과 확인 영역(렌더링/코드)
- 사용자 이동 순서: 카테고리 선택 → 태그 선택 → 속성 입력 → 제작 → 배치 → (렌더링부/코드부에서 결과 확인) → 필요시 반복

## 접근성 (최소 2가지 적용)

1. **버튼을 색만으로 구분하지 않음**: 초기화 버튼은 색으로만 위험도를 표시하지 않고, 클릭 시 확인 모달을 한 번 더 거치도록 해서 색을 구분하기 어려운 사용자도 실수로 작업 내용을 잃지 않도록 함
2. **사용자가 화면 비율을 직접 조정 가능**: 렌더링부와 코드부 사이 구분선을 드래그해서 좌우 비율을 조정할 수 있어, 코드부 글씨를 더 크게 보고 싶은 사용자(저시력 사용자 등)가 자신에게 맞게 화면을 조절할 수 있음

> (와이어프레임 파일에도 이 두 가지를 어디에 적용했는지 동일하게 밝혀둘 것)

## AI 활용 내역

- **기획서**: Claude와의 브레인스토밍을 통해 아이디어 구체화와 문서 정리 과정을 함께 진행했습니다.
- **와이어프레임**: 제출물의 와이어프레임은 HTML·CSS·JS로 이루어져 있습니다. 핵심인 작업 화면(workspace.html)의 레이아웃과 디자인은 직접 만들었습니다.
- **추가한 두 페이지**: 소개 페이지와 대시보드는 제출 하루 전, 사용자에게 필요한 페이지가 무엇일지 직접 구상하고 각 페이지의 배치를 정한 뒤 추가했습니다. 시간이 부족해 이 두 페이지의 레이아웃 와이어프레임 구현에만 Claude Code를 사용했고, 직접 만든 workspace.html의 스타일·디자인·코드 작성 방식을 그대로 따르도록 했습니다. 기능 구현(JS)은 파일과 역할 주석만 만들어둔 상태이며, 실제 동작 코드에는 AI를 사용하지 않았습니다.
- **앞으로의 계획**: AI가 작성한 부분을 그대로 가져다 쓰지 않을 것입니다. 개발에 들어가기 전에 해당 코드를 직접 한 줄씩 읽어 이해하고, 제 의도와 다르거나 고칠 부분은 직접 수정한 뒤 개발에 착수할 계획입니다. 딸깍은 제가 HTML을 배우며 느낀 불편에서 출발한 프로젝트인 만큼, 제 손으로 이해하고 만든 코드로 완성하는 것을 목표로 합니다.
